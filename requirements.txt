# PyTorch CPU-only index.
#
# `sentence-transformers` requires `torch`, and torch's default PyPI wheel for
# Linux declares its CUDA runtime as hard dependencies, gated behind
# `platform_system == "Linux"` markers:
#
#     nvidia-cudnn-cu13, nvidia-nccl-cu13, nvidia-cusparselt-cu13,
#     nvidia-nvshmem-cu13, triton            (torch 2.13.0)
#
# Those markers are false on Windows and macOS and true on Railway, which is
# exactly why this installed cleanly on a laptop and then failed in CI: several
# gigabytes of GPU runtime for a container that has no GPU.
#
# The `+cpu` build published on the index below is the same torch version with
# those dependencies absent (10 requirements, none of them CUDA). Verified by
# reading both wheels' METADATA directly.
#
# This index is additive: `+cpu` local versions exist only here, so the torch
# pin below cannot silently resolve back to the PyPI GPU wheel.

# Torch is pinned explicitly even though nothing imports it directly: it is a
# transitive dependency of sentence-transformers, and leaving it implicit is
# what let the GPU build in. Declaring it here is what makes the `+cpu`
# variant win.
#
# Linux only. Windows and macOS already resolve to CPU-only builds from PyPI,
# and no `+cpu` wheels are published for macOS, so pinning it there would break
# local development for no benefit.
